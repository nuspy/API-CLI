API-CLI v0.3.0

Orchestrazione multi-agente per CLI tools di AI coding.
Due interfacce: War Room (web app) e PSLLMKit (PowerShell).

API-CLI permette di usare più agenti AI (Claude, Codex, Gemini, Droid) da un'unica interfaccia. Gli agenti possono collaborare tra loro, discutere su task di codice e modificare file nella tua working directory — con safety net via git checkpoint.

Prerequisiti

  • Node.js ≥ 18 (per la web app)
  • PowerShell ≥ 7.0 (per PSLLMKit)
  • Git installato e nel PATH
  • Almeno uno dei CLI tools installato e autenticato:

Claude Anthropic

Comando: claude
Auth: OAuth automatico

Codex OpenAI

Comando: codex
Auth: OPENAI_API_KEY

Gemini Google

Comando: gemini
Auth: GEMINI_API_KEY

Droid Factory

Comando: droid
Auth: OAuth automatico

Verifica l'installazione:

claude --version
codex --version
gemini --version
droid --version

War Room — Web App

La War Room è un'interfaccia web che permette a più agenti AI di collaborare in una chat condivisa. Tu invii un messaggio, gli agenti rispondono e discutono tra loro in round successivi, fino a convergenza o stop manuale.

Installazione e avvio

# Vai nella directory webapp
cd D:\Projects\API-CLI\webapp

# Installa le dipendenze (solo la prima volta)
npm install

# Avvia in modalità development
npm run dev

Si apriranno due server:

  • Vite (frontend) → http://localhost:5173
  • Express (backend + WS) → http://localhost:3001

Apri http://localhost:5173 nel browser.

Modalità produzione

# Build del frontend
npm run build

# Avvia solo il server Express (serve i file statici da dist/)
npm start

In produzione tutto gira su http://localhost:3001.

Come si usa

  1. Imposta la Working Directory
    Nella sidebar, inserisci il path della directory su cui vuoi lavorare (es. D:\Projects\MyApp) e clicca Set.
    Se non è un repo git, ne verrà creato uno automaticamente.
  2. Aggiungi gli agenti
    Scegli il tipo (claude, codex, gemini, droid), dai un nome custom opzionale, e clicca +.
  3. Seleziona i target
    Sotto l'area di input, le checkbox ti permettono di scegliere a quali agenti inviare il messaggio. Di default sono tutti selezionati.
  4. Invia il messaggio
    Scrivi nel campo di testo e premi Enter (o clicca Send). Shift+Enter per andare a capo.
  5. Osserva la discussione
    Gli agenti rispondono e vedono le risposte degli altri. La discussione procede in round (max 10). L'indicatore in alto mostra il round corrente.
  6. Stop o convergenza
    La discussione si ferma quando tutti gli agenti rispondono [PASS] (convergenza) o quando premi Stop.

Gestire gli agenti

Ogni agente nella sidebar mostra:

  • Pallino di stato: grigio (idle), verde pulsante (thinking), rosso (error)
  • Badge colorato con il tipo di CLI tool
  • ↻ — Reset della sessione (solo per agenti con sessione: Claude, Droid)
  • × — Rimuovi l'agente

Puoi aggiungere più agenti dello stesso tipo con nomi diversi (es. due Claude con ruoli diversi).

Sessioni: Claude e Droid mantengono una sessione nativa. Nelle invocazioni successive il CLI ricorda il contesto precedente. Codex e Gemini ricevono invece l'intera storia della conversazione ad ogni invocazione.

Discussioni multi-round

Il motore di discussione funziona così:

  1. Il tuo messaggio viene inviato a tutti gli agenti selezionati in parallelo.
  2. Ogni agente risponde. Le risposte appaiono in chat in tempo reale.
  3. Le risposte di un round diventano contesto per il round successivo.
  4. Se un agente risponde [PASS], viene escluso dai round successivi.
  5. Quando tutti passano → convergenza naturale.
  6. Massimo 10 round, poi stop automatico.
  7. Puoi premere Stop in qualsiasi momento per terminare tutti i processi.
Timeout: Ogni agente ha un timeout di 5 minuti. Se un agente non risponde in tempo, il suo processo viene terminato e l'errore viene mostrato in chat.

Git checkpoint & undo

Ogni volta che inizia un nuovo round, la War Room esegue un git checkpoint automatico (git add -A && git commit). Questo permette di tornare indietro se un agente fa modifiche indesiderate.

  • Undo Last Round (pulsante nella sidebar) → esegue git reset --hard al checkpoint precedente.
  • Puoi fare undo multipli (uno per ogni round).
  • All'avvio viene creato un branch dedicato warroom-{timestamp}.

PSLLMKit — Modulo PowerShell

PSLLMKit è un modulo PowerShell che fa da gateway REST verso i CLI tools di AI. Ogni app (Claude, Codex, Gemini, Droid) può essere avviata come server HTTP indipendente con i propri endpoint, oppure invocata direttamente senza server.

Installazione

# Importa il modulo
Import-Module D:\Projects\API-CLI\PSLLMKit.psd1

# Verifica
Get-Module PSLLMKit

Comandi disponibili

CmdletDescrizione
Start-LLMServer Avvia un server REST per un app su una porta specifica
Stop-LLMServer Ferma un server (per app o tutti)
Get-LLMServerStatus Mostra lo stato dei server attivi
Invoke-LLMPrompt Invoca un CLI tool direttamente (senza server)
Get-InstalledCLITools Elenca i CLI tools installati e disponibili
Register-CLITool Registra un nuovo CLI tool custom
Invoke-CLITool Invocazione low-level di un CLI tool

Modalità Server REST

Ogni app gira come server HTTP indipendente su una porta a scelta:

# Avvia Claude sulla porta 8081
Start-LLMServer -App claude -Port 8081

# Avvia Droid sulla porta 8082
Start-LLMServer -App droid -Port 8082

# Vedi chi è attivo
Get-LLMServerStatus

# Ferma un server specifico
Stop-LLMServer -App claude

# Ferma tutti
Stop-LLMServer -All

Endpoint API

Ogni server espone questi endpoint:

MetodoPathDescrizione
POST /api/prompt Invia un prompt. Body: { "prompt": "...", "model": "...", "systemPrompt": "..." }
GET /api/status Info sull'istanza: app, porta, uptime, session ID
POST /api/session/reset Reset della conversazione (cancella session ID)
GET /api/health Health check

Esempio con curl

# Invia un prompt a Claude
curl -X POST http://localhost:8081/api/prompt \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Spiega il pattern Observer in 3 righe"}'

# Risposta:
# { "content": "...", "sessionId": "abc-123", "duration": 4200 }

Invocazione diretta (senza server)

Puoi invocare un CLI tool direttamente senza avviare il server:

# Prompt singolo a Claude
Invoke-LLMPrompt -App claude -Prompt "Come funziona async/await?"

# Con modello specifico
Invoke-LLMPrompt -App gemini -Prompt "Refactora questo codice" -Model "gemini-2.0-flash"

# Con sessione (per continuare una conversazione)
$r = Invoke-LLMPrompt -App claude -Prompt "Crea una funzione di login"
Invoke-LLMPrompt -App claude -Prompt "Aggiungi validazione" -SessionId $r.SessionId

L'output è un oggetto PSLLMKit.Response:

ProprietàTipoDescrizione
ContentstringLa risposta dell'agente
AppstringIl tool usato (claude, codex, ecc.)
ModelstringIl modello usato
SessionIdstringID sessione (per continuare la conversazione)
DurationintDurata in millisecondi
TimestampdatetimeTimestamp della risposta

Troubleshooting

"command not found" per un CLI tool

Il tool non è installato o non è nel PATH. Installa il tool e riavvia il terminale. Verifica con where claude (Windows) o which claude (Unix).

Porta già in uso

Un altro processo usa la porta. Cambia porta o chiudi il processo: 

# Trova chi usa la porta 3001
netstat -ano | findstr :3001

# Oppure per PSLLMKit, usa una porta diversa
Start-LLMServer -App claude -Port 8090

WebSocket non si connette

Assicurati che il server Express sia in esecuzione sulla porta 3001. In dev mode, Vite fa proxy automatico verso il backend.

Agente non risponde (timeout)

Il timeout di default è 5 minuti. Se l'agente è lento (es. task complessi), il processo viene terminato dopo il timeout. Controlla che il CLI tool sia autenticato correttamente eseguendolo manualmente: claude -p "test".

Undo non funziona

L'undo richiede che la working directory sia impostata e sia un repo git valido. Verifica che il pallino "Git ready" sia verde nella sidebar.

Errori di importazione PSLLMKit

# Assicurati di usare PowerShell 7+
$PSVersionTable.PSVersion

# Importa con path assoluto
Import-Module D:\Projects\API-CLI\PSLLMKit.psd1 -Force -Verbose
